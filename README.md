# MOEX OFZ Analytics Tracker

Компактный и оптимизированный пет-проект для автоматизированного учёта, скоринга и прогнозирования доходности портфеля ОФЗ (Облигаций Федерального Займа) на базе данных Московской Биржи (MOEX ISS API). 

> 📱 **Особенность разработки:** Проект изначально проектировался и тестировался в среде **Pydroid 3 (Android)** как полностью автономный мобильный трекер. В ходе разработки кодовая база была глубоко оптимизирована (полный отказ от Pandas в пользу встроенных структур данных), что позволяет скриптам летать даже на слабых смартфонах, сохраняя при этом strict-архитектуру для будущего деплоя на VPS.
 
Разработан с учётом строгой модульной архитектуры (Separation of Concerns), что позволяет бесшовно перенести UI-слой с текущего CLI на веб-фреймворк FastAPI.

## ✨ Ключевые фичи и бизнес-логика
* **Расчёт реальной текущей доходности:** Вычисляет купонную доходность от текущей рыночной цены на бирже в режиме реального времени (многие брокеры скрывают этот показатель в приложениях).
* **Очистка от НДФЛ (-13%):** Автоматический расчёт «чистой» доходности (Yield Net) для каждой бумаги и по портфелю в целом.
* **12-месячный прогноз выплат:** Динамическое построение календаря купонных выплат на год вперёд с детализацией по месяцам и конкретным тикерам.
* **Локальный кэш и синхронизация:** Состав портфеля хранится в локальной БД SQLite, синхронизируясь из легковесного JSON-файла конфигурации.

## 📐 Архитектура проекта
Код спроектирован по слоям для обеспечения высокой поддерживаемости и масштабируемости:
1. `constants.py` — Слой конфигурации (эндопинты API, заголовки, параметры путей БД).
2. `database.py` — Слой данных (Data Provider). Инициализация таблиц SQLite, миграция и синхронизация структуры. Без побочных эффектов вывода.
3. `moex_client.py` — Сетевой слой (API Client). Изолированное взаимодействие с MOEX ISS API, обработка таймаутов.
4. `services.py` — Слой бизнес-логики (Domain Layer). Чистые функции расчёта финансовых метрик, агрегации аналитики портфеля и генерации календаря выплат. Не зависит от интерфейса.
5. `main.py` — Точка входа (Orchestrator / UI Layer). На текущем этапе выполняет роль CLI-интерфейса.

> 🚀 **Готовность к FastAPI:** Благодаря изоляции бизнес-логики в `services.py`, перевод проекта на API-эндпоинты займет всего несколько строк кода. Функция `aggregate_portfolio_analytics` возвращает чистый Python-словарь, который FastAPI автоматически сериализует в JSON.

## 🛠 Стек технологий и среда
* **Language:** Python 3.10+
* **Database:** SQLite (интегрирована через стандартный `sqlite3`)
* **Network:** `requests` для работы с REST API Мосбиржи
* **Среда разработки (Mobile):** Pydroid 3 / Termux (Android) с полной поддержкой вывода логов в консоль смартфона и сохранением истории в `app_bonds.log`.
* **Целевая среда деплоя (Production):** Ubuntu Linux (VPS) + FastAPI.

## 🚀 Инструкция по запуску

### 1. Подготовка конфигурации портфеля
Создайте в корневой директории файл `portfolio.json` и укажите ваши тикеры ОФЗ и их количество:
```json
{
  "SU26230RMFS1": 150,
  "SU26233RMFS5": 200,
  "SU26240RMFS0": 250
}
```

### 2. Установка зависимостей
Для работы скрипта требуется только библиотека `requests` (тяжеловесный Pandas был успешно выпилен в ходе оптимизации производительности):
```bash
pip install requests
```

### 3. Запуск трекера
```bash
python main.py
```
